# 05 · Светомузыка без работающей Яндекс Станции

[← Управление](03_CONTROL_RU.md) · [Начало](00_START_RU.md) · [Диагностика](04_RECOVERY_RU.md) · [English](05_COLOR_MUSIC_EN.md)

**Что доказано 11 ноября 2026 года:** Эмби Лампа YNDX-00560 включила Color music через независимый Matter.js и визуально пульсировала от UDP/4048-кадров, отправленных Ubuntu. Тот же опыт прошёл при **физически отключённой Яндекс Станции**.

> Это **результаты аппаратного эксперимента**, а не готовая к копированию установка. Исходные скрипты и образ с vendor patch существуют пока в локальной исследовательской папке и **не опубликованы** в этом репозитории. Нового commissioning для включения светомузыки не требуется.

## Как это работает

~~~mermaid
flowchart LR
  subgraph Linux["Ubuntu / независимый контроллер"]
    M["Matter.js<br/>Fabric 2"]
    P["Источник UDP-кадров<br/>replay"]
  end
  M -->|"Matter UDP/5540<br/>SetEnable + SetAnimation"| L["YNDX-00560"]
  P -->|"UDP/4048<br/>490 B / кадр"| L
  Y["Яндекс Станция<br/>Fabric 1"] -. "Не нужна во время<br/>проверенного replay" .- L
~~~

**Matter** включает режим. **UDP** передаёт спектроподобные данные, на которые реагирует лампа. После включения Color music **без UDP-пакетов** лампа светилась статично.

## Что должно быть готово

1. Лампа уже добавлена в **независимую** Matter Fabric ([как это сделать](02_PAIR_RU.md)). Этот эксперимент не заменяет первый pairing.
2. Сохранены исходное состояние лампы (OnOff/цвет/режим/яркость), приватный backup Matter.js `/data` и рабочий rollback.
3. В эксперименте использовался образ `1.5.5-direct-color-music-v1` с ограниченным vendor-command patch. **Это локальный образ, которого нет в GitHub.** Не заменяйте действующий `1.5.5-direct-v1` без проверки и резервной копии.
4. Ubuntu может отправлять UDP на порт назначения `4048` лампы. Не выставляйте Matter WebSocket в интернет.

## 1. Включаем Color music через Matter.js

Подтверждённый Matter-контракт: **endpoint 1**, vendor cluster `0x132FFC06`.

| Команда | ID | Payload | TLV |
|---|---|---|---|
| `SetEnable` | `0x132F0001` | `{enable: true}` | `15 29 00 18` |
| `SetEnable` | `0x132F0001` | `{enable: false}` | `15 28 00 18` |
| `SetAnimation` | `0x132F0002` | `{animationId: uint8}` | `15 24 00 <id> 18` |

Рабочая последовательность: **`SetEnable(true)` → `SetAnimation(0)`**. Лампа объявляла ID анимаций `[0,1,2]`, но **только 0 фактически испытан**. Затем отдельное чтение подтвердило:

| Атрибут | Результат |
|---|---|
| `OnOff` | `true` |
| `enable` | `1` |
| Vendor category | `3` — `Color music` |

~~~mermaid

    participant L as Лампа
    participant U as Ubuntu
    M->>L: SetEnable(true)
    M->>L: SetAnimation(0)

    Note over L: Пока нет UDP, свет статичен
~~~

**Важно:** в текущем публичном CLI `tools/matter_lamp/matter-lamp-client.mjs` нет опубликованной команды для Color music. Не пытайтесь вызывать её через `set_scene`: это другой кластер и другая функция.

## 2. Передаём UDP/4048

Подтверждённый UDP **payload: 490 байт** на кадр.

~~~text
offset 0..9     10 B    header = 41 00 a9 01 00 00 00 00 01 e0
offset 10..489  480 B   120 x unsigned uint32 (big-endian)
total           490 B   destination UDP/4048
~~~

~~~mermaid
flowchart LR
    P["UDP payload<br/>490 bytes"] --> H["Header<br/>10 bytes"]
    P --> B["Body<br/>480 bytes"]
    B --> F["120 x uint32 BE<br/>точное значение частот неизвестно"]
~~~

В штатном захвате исходный UDP-порт был `44207`. Это **наблюдение, а не обязательное требование**. Успешная отправка с Ubuntu показала, что **в проверенной конфигурации** лампа не требовала исходного IP Яндекс Станции.

| Аппаратный тест | Результат |
|---|---|
| 1 оригинальный пакет | PASS |
| 98 пакетов за ~2 секунды | PASS |
| 245 пакетов за ~5 секунд | PASS, видна пульсация |
| Станция обесточена, независимое Matter enable + 245/245 кадров | PASS, видна пульсация |

Средняя скорость replay — около **49 кадров/с**. Не путайте её с частотой **уникальных** спектральных обновлений.

## 3. Проверяем работу без Станции

В ходе отдельного опыта Станцию физически выключили: её SSH стал недоступен. Ubuntu, Matter.js и лампа продолжили работать. `SetEnable`, `SetAnimation(0)` и UDP replay 245/245 кадров снова прошли, пульсация наблюдалась.

**Вывод:** работающая Станция не нужна ни как источник UDP, ни как посредник Matter для **уже сопряжённой** лампы в этой тестовой конфигурации. Способ первичного pairing без Станции таким образом **не доказан**.

## 4. Откат и диагностика

После завершения теста:

1. `SetEnable(false)` → отдельный readback `enable=0`.
2. Восстановить **свою** исходную категорию и цвет/яркость/температуру, затем `OnOff`.
3. Проверить Matter.js: `healthy`, restart count `0`, узел доступен, `/data` сохранён.
4. Если Станция отключалась, включить её; проверить `maind --platformd` и закрытый TCP/8765.

**Итоговые фактические значения сеанса:** `OnOff=false`, категория `Color`, Hue/Saturation `52/244`; Станция загрузилась штатно, TCP/8765 закрыт. **Не используйте `52/244` как универсальный baseline** — на другом устройстве исходное состояние иное.

При статичном свете проверьте `enable`/category и наличие **фактически доставленных** UDP-кадров, а не повторяйте commissioning или vendor Invoke вслепую.
